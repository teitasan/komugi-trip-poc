# こむぎの旅 — Web POC

小さな犬のぬいぐるみ「こむぎ」が、現実の福岡の地図上を自律的に旅行する見守りアプリです。

## 起動

Node.js 22.13以上が必要です。依存関係と初回のローカルDBは準備済みです。

```sh
cd /Users/apple/7masu/komugi-trip
npm run dev -- --port 5180
```

プレビュー: http://localhost:5180/

編集用データ台帳: http://localhost:5180/data-editor.html

データ台帳の表はブラウザ上で直接編集できます。編集内容はブラウザ内に保存でき、JSONを書き出して次のデータ反映に渡せます。台帳は現在のシミュレーションへ自動反映する管理画面ではなく、観光地・食事・宿泊データを受け渡すための編集用画面です。

Nodeが見つからない環境では、同梱の `start-local.command` を実行してください。

## 体験できること

- 博多発、3日・7日の旅行。1日7,000〜30,000円をまとめて支給。
- 食いしん坊・節約家・鉄道好き・海辺好きの4つの性格。
- 18の地点（出発地点1・観光地17）、16種類の食事、6種類の宿から、予算・距離・営業時間・性格に応じて選択。ご当地料理に加えて、コンビニ弁当・牛丼・ハンバーガーも低い重みで含みます。
- 宿泊はネットカフェ（2,500円）を基本にし、予算内に有料の宿がない場合だけ野宿（0円）へ切り替えます。
- 食事は日本時間の営業時間を見て選び、21時以降は24時まで営業するチェーンの重みを上げます。23時台にまだ夕食を取っていなければ、チェーンを優先してから宿へ向かいます。
- 徒歩・電車だけの移動。福岡市地下鉄3線、JR3系統、西鉄3系統の駅・路線データから経路・運賃・所要時間を算出し、経過時間から現在位置を補間。
- 行き先は観光地・公園・海辺などの地点から抽選し、駅はその地点へ向かうアクセス手段として使う。
- 食事・観光・宿泊・帰宅と、そのたびの収支・キャラクターの日記。
- 出発5分後の最初の写真。海・ラーメン・こむぎの3種類の事前生成画像。
- 追加支給、1時間・6時間・1日の早送り。早送り後も実時間の経過が続く。
- 帰宅後の集計、アルバム、過去の旅の選択。
- 同じブラウザでの継続。状態と全支出ログをローカルD1/SQLiteに保存。

## POCの範囲

- 地図はLeaflet + OpenStreetMap。Google Maps APIキーは不要です。
- 鉄道は福岡市周辺の主要駅を並べた路線グラフで、運賃・所要時間はPOC用の近似値です。実際の道路経路・時刻表・最新運賃の保証やライブ検索はありません。
- おこづかいはゲーム内の仮想予算です。実際の予約・課金は行いません。
- 天候は `sunny` 固定。観光地ごとの開場時刻・閉場時刻を考慮し、滞在時間全体が営業時間内に収まる経路だけを選びます。営業時間外に到着した場合は、開場まで待機します。
- 写真はAI生成のイメージ素材です。地点ごとの正確な外観再現はせず、一部素材を再利用します。
- 未起動中のイベントは、次のアクセスで予定時刻順に復元します。常駐スケジューラ・アプリを閉じた間のプッシュ通知は未実装です。
- ローカルプレビューは端末のサーバー起動が必要です。停止中も開始時刻からの経過時間は再起動後に反映します。
- 所有者はHttpOnly CookieのランダムなセッションIDで識別します。ログイン、端末間同期、Cookie削除後の回復UIは未実装です。
- 旅行データは `.wrangler/state` に保存されます。このフォルダを削除すると記録を失います。
- 公開リポジトリ: https://github.com/teitasan/komugi-trip-poc

## 主な実装

- `app/components/journey-app.tsx`: 旅じたく、現在地、日記、アルバム、収支。
- `app/components/journey-map.tsx`: 地図と移動位置。
- `lib/travel-data.ts`: 観光地点、地点から駅への徒歩アクセス、福岡市周辺の駅・路線グラフ、食事、宿のデータ。
- `lib/simulation.ts`: 再現可能な乱数、時刻順の行動、予算確保、経路選択と位置補間。
- `public/data-editor.html`: 観光地・食事・宿泊を表形式で編集し、JSONで受け渡すためのデータ台帳。
- `app/api/trip/route.ts`: セッション単位の読書き、入力検証、楽観ロック、操作IDによる重複排除。
- `db/schema.ts` / `drizzle/0000_goofy_vector.sql`: DBスキーマ。旅行状態とログを1行のJSONとして原子的に保存。

## 検証

```sh
node scripts/check-simulation.mjs
node scripts/check-api.mjs   # localhost:5180のサーバーが必要。独立した検証用セッションに旅を作成する
npx tsc --noEmit
npm run build
```

シミュレーションは360通り（日数×予算×性格×開始時刻×乱数）で、帰宅期限・残金・支出合計・再実行・アクセス頻度に依存しない進行を検証します。
API検証は保存、同時実行時の追加支給の重複防止、不正入力、オリジン、早送りの再試行、旅行履歴、別セッションの分離を確認します。
